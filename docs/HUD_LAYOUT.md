# HUD 布局与验收

本轮只调整展示和入口，不改变玩法、存档或控制规则。

## 布局约定

- 左上：两行当前目标，可点击进入成长手记；航海收集统计放在已有航海手记面板。
- 右上：日期 / 星期、时间、天气为第一组；真实金币、体力、设置为第二组。用正常文档流布局，不分别绝对定位。
- 底部：1～8 物品快捷栏；左下菜单按钮（Tab），右下沉浸开关（F10）。导航、时间倍率、声音、画质、观察点均移至快捷菜单。
- 菜单使用原生模态框；打开时暂停玩家输入和车辆，关闭后恢复控制，选择入口先关闭菜单，再交给原有面板。
- 状态优先级：过场 > 对话 > 面板 > 航海 > 驾驶 > 钓鱼 > 步行 > 瓶外。背景 HUD 在模态面板打开时隐藏，避免输入竞争。
- 普通交互提示保持右侧中央；驾驶动作置于车辆卡片的正常布局流内，避免展开挂接帮助后重叠。临时通知按顺序堆叠，驾驶窄屏通知与车辆卡片各有独立空间。
- 提示按场景首次进入显示数秒，同一帧重复更新不延长；可在菜单随时查看操作帮助。交互目标提示和钓鱼 / 农机工作状态仍及时显示。
- 沉浸模式隐藏常驻装饰，保留交互、张力、农机状态、紧急通知；F10 和出口按钮始终可恢复。
- 窄屏采用上下排布，短屏缩小组件；安全边距使用 safe-area 与动态视口，菜单和长内容内部滚动。
- 新 HUD 组件复用 `hud-layout.css` 中的安全边距、蓝色轻面板及情境规则；业务面板继续使用原有共享 UI 样式。不要新增常驻绝对定位入口。

## 实施与验收

1. 抽出纯展示策略和提示寿命；接入 HUD 菜单与统一区域。
2. 复用原入口，迁移钱包、快捷栏、目标、农田和车辆反馈；不复制任何业务状态。
3. 检查快捷键、模态互斥、输入恢复、不同场景的必要状态和提示。
4. 执行 typecheck、test、build；浏览器实际检查 16:9、16:10、窄屏、短屏 / 缩放等效视口、钓鱼、驾驶、室内、航海、NPC 与功能面板。

验证结果另见 `HUD_VALIDATION.md`。
