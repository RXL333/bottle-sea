# 农用拖车运输

## 操作与运输闭环

- 使用现有拖车 GLB 和后挂点。拖拉机停稳，对准拖车连接点，按 **H** 挂接 / 分离；步行靠近连接点也可按 **E**。原前进、转向、倒车、碰撞和安全下车继续使用 HitchSystem / VehicleController。
- 联合收割机停在拖车侧面，使卸粮管出口对准车厢。双方停稳并关闭收割作业，在收割机上按 **U** 装粮。检测实际卸粮口与旋转后的车厢，不是只检查车辆中心距离。
- 拖车 **120 份总容量、4 格**，每格堆叠上限仍由 ItemRegistry 定义，允许混装。HUD 显示货物名称、数量和剩余容量；车厢简单货物块随载量变化，不做散粒物理。
- 挂接拖车后开到谷仓门前虚线卸货区，**车厢**进入范围、车组停稳，拖拉机上按 **U** 卸入谷仓。农田或道路上不能卸货；未挂接的拖车先挂车再运输。
- 下车靠近停稳车厢按 **E** 打开复用的背包 / 货仓网格。支持单个、整堆、Shift 快速存取、拖拽、拆分和全部存入，显示格数及总装载量。可运输统一 ItemRegistry 中的物品。
- 谷仓仓库沿用现有 **E** 存取。收割机也仍可停车直接卸入谷仓。

## 容量、事务和存档

`Inventory` 增加可选 `quantityCapacity`；添加、交换、拖拽、跨容器换位及加载都遵守上限。默认背包 / 小屋 / 谷仓容量及原整笔转移接口保持原行为。

`transferAvailableTo(target, {slot?, quantity?})` 在试算库存中按目标堆叠空间、空格和总量限制计算可以转移的货物。两个容器先同时提交，再调用所有 `beforeNotify` 发布车辆所有权快照，最后发保存通知。接收方不足只移动可容纳的数量；其他货物留在原处。满载重复操作没有变更或保存回调。

`FarmTransportSystem` 只检查空间和停车条件并调用库存 API。拖车复用 ImplementVehicle、drawbar 连接及整车组碰撞；没有农业状态修改，没有新库存计数或独立作物计时。

`ImplementPose.cargo` 保存槽位 / 堆叠 / 选择，与位置、方向和挂接关系一起进入既有 VehicleSnapshot / SaveData version 2。缺失 cargo 的旧存档恢复空车；无效物品与超容量内容安全归一化。保存仅 JSON，装载 Mesh 重新生成。收割机、拖拉机和拖车的保存互不覆盖。

## 开发复现

仅在隔离测试来源使用 `?world=farm&view=farm-transport&fixture=1&fill=1&persist=1&hour=10`：显式将已挂接车组对准卸粮口，并通过统一 API 准备收割机小麦 60、拖车玉米 100、背包木材 10。U 仅移动小麦 20，收割机余 40。生产构建没有该入口，不会赠送货物。

去掉 fixture / fill / hour 后验证普通恢复；`driver=tractor` 定位到拖拉机上车侧，`onfoot=1` 到车厢侧。`view=farm-transport-barn&fixture=1` 仅定位车组到谷仓，不新增货物，便于测试停车卸货；实际驾驶仍由原输入处理。

新增测试覆盖单位容量所有入口、部分混货、原整笔转移兼容、双方保存原子性、真实 GLB 装卸范围、速度 / 收割限制、谷仓部分容量、载货转弯 / 倒车 / 碰撞、挂接与分离恢复、旧存档兼容。浏览器实玩结果见本文件后续验证记录。

- `npm run typecheck`、`npm test`、`npm run build` 通过，49 个测试文件、214 项测试。新增 12 项；现有 Home / Fishing / Cooking / 农业 / 车辆检查继续通过。
- 隔离浏览器来源 `127.0.0.1:5194`，通过真实 E / U / H 和驾驶输入验证。显式 DEV fixture 用于准备货物及装卸站定位；不覆盖用户正常存档。站间全程路线未自动驾驶，满载前进、转弯、倒车独立实测；基础碰撞通过真实 GLB 集成测试验证。
- 收割机小麦 60、拖车玉米 100：实际 U 仅移动小麦 20，拖车 120/120、收割机余 40，再按 U 不变化。普通重新进入恢复原位置、挂接、混货及余粮。
- 满载拖车实际前进、左转和倒车后仍是 120 份，车厢和连接随车移动。下车 E 打开网格，满载全部存入拒绝；取出小麦 1，再 Shift 快速存入木材 10，实际仅存 1，背包余 9。最后取回木材并存回小麦，恢复原组合，数量守恒。
- 谷仓实际 U 卸入玉米 100 / 小麦 20，拖车清空，再按 U 拒绝。之后装入收割机余下小麦 40，实际 H 分离；普通重新进入仍为分离状态、原位置和小麦 40。重新 H 挂接后到谷仓 U 卸完。
- 最终普通重新进入（无 fixture / fill / hour）恢复空收割机、空拖车和挂接位置；实际下车步行靠近谷仓 E，仓库显示玉米 100、小麦 60，背包木材 10。初始与最终 160 份粮食一致，控制台无 error / warn。
