# 正式背包系统

## 实施范围与顺序

1. ItemRegistry 为物品定义的唯一来源：分类、描述、SVG 图标、堆叠上限、食用恢复、鱼类属性；Recipe 只保存制作规则。
2. 保留背包与小屋箱子各 24 格。ItemDefinition 与持有的 ItemStack 分离，Inventory 统一增减、交换、槽位移动、拆分、丢弃与跨容器转移。
3. 6 列网格、详情、分类筛选、Hover / Select、容量；同一面板提供背包与箱子模式。B 打开背包，E 打开箱子。
4. 8 格快捷栏只保存 itemId 引用，数量从背包读取；1～8 选中，Q 使用已选食物。拖入或选择后绑定，不另建库存。
5. 拖拽换位 / 合并；选择数量拆分到空槽；Shift 点击快速转移整堆，支持转移一个与全部存入。容量不足不丢失物品。
6. 沿用 v2 key，兼容此前 v1/v2，保存背包槽位数量、选中槽位、快捷栏绑定/选中、箱子槽位和已有玩法状态。
7. 按用户约定只进行 TypeScript 与代码检查，游玩验收由用户完成；不扩展装备、耐久、重量或 RPG 系统。

## 待用户验收

- 捕获的鱼显示图标与数量，详情显示名称、描述、分类和堆叠上限。
- 自动堆叠、满堆换槽、换位、合并、拆分、丢弃后数量一致；容量满有明确提示。
- 全部 / 食物 / 鱼类 / 作物 / 种子 / 材料 / 工具 / 特殊筛选不修改真实槽位。
- 快捷栏数量随背包、烹饪、食用、存取和丢弃变化，拖拽或拆分不复制库存。
- 仓库单个、整堆与全部存入正确；容量不足不部分扣除。
- 刷新、进出小屋、岛屿往返后数量、槽位、快捷栏与选中状态恢复。
- 原钓鱼、炉灶、储物、睡觉、鼠标锁定继续可用。

## API 与持久化

- 定义集中在 `src/gameplay/ItemRegistry.ts`，12 个现有物品使用本地原创 SVG 图标；不把名称、分类、描述或图标写入玩家 Stack。
- `InventorySlot = ItemStack | null`，槽位数组索引稳定；快照包含 capacity / slots / selectedSlot。add 自动合并与换槽，remove 按 itemId 扣数量；槽位操作可精确移动或丢弃指定堆叠。
- `moveSlotTo`：同容器换位或跨容器拖拽；相同物品填至上限，余量保留源槽；不同物品只有整堆才能交换。
- `splitStack`：数量必须小于源堆叠，目标为空；`transferSlotTo` 精确取自源槽，目标自动堆叠；`transferAllTo` 整笔提交，不能全部容纳时不修改任一容器。
- `HotbarSnapshot = { bindings: (string | null)[], selectedIndex }`，固定 8 位。引用物品用尽后保留图标并显示 0，补入后自动恢复可用；数量始终由 Inventory.count 派生。
- 旧 v2 没有 hotbar / selectedSlot 时补默认值，原物品 ID、堆叠上限和箱子容量保持。已有 home 空箱不重复补发初始资源。
- 背包与储物箱面板开启期间暂停探索和日历，关闭后从原位恢复之前的鼠标操作方式。F 随身食物与炉灶面板仍使用同一个 Inventory / CookingSystem。
