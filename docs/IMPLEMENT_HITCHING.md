# 拖拉机农具挂接与分离

本阶段完成已有犁地机、播种机、拖车的挂接与分离。沿用 FarmWorld、InteractionSystem、VehicleController、共享镜头和 SaveSystem，没有新增农业作业或货物库存。

后续阶段已增加 J 抬落与共享农业作业，详见 [挂犁耕地说明](TRACTOR_PLOWING.md) 和 [播种机说明](TRACTOR_SEEDING.md)。以下验证记录保留挂接阶段的交付范围；拖车仍无运输逻辑。

## 操作

1. 将拖拉机停在农具前方，倒车对准两个连接点。按 Space 停稳。
2. 车上按 **H** 挂接；也可以下车，站在农具连接点旁按 **E**。
3. 农具随车前进、转向和倒车。停稳后再次按 H，或步行到连接点按 E，分离农具。

犁地机兼容 Hitch_Back / Hitch_Front；播种机和拖车使用 Hitch_Back。每个挂点最多连接一件农具，每件农具只能有一项连接关系。E 在驾驶状态下仍负责下车。

挂接要求：速度不超过 0.12m/s、两个连接点的水平距离不超过 0.55m、横向错位不超过 0.28m、朝向偏差不超过 25°、挂点高度差不超过 0.25m。提示会显示距离、朝向、挂点占用或停稳条件。分离位置需要有地面并避开车身、其他农具、玩家和地图障碍；空间不足时保留原连接关系。

## 数据与模型

- `ImplementRegistry` 仅定义农具 ID、模型、挂点兼容性和连接类型。运行时姿态在 `ImplementVehicle`，持久状态在 `VehicleProgress`。
- 原有 Blender / GLB 几何继续使用。拖拉机保留 Body、Seat、四个轮轴和 Hitch_Back，增加 Hitch_Front；三件农具增加带 `part_id` 的 Hitch_Front 连接标记。生成脚本、资源 JSON 和 manifest 同步更新。
- `HitchSystem` 管理唯一关系、对准检查、连接杆和地面定位。犁、播种机保持固定方向；拖车按牵引点位移更新铰接方向，限制最大偏角，防止倒车折叠。
- 沿用车辆 120Hz 最大子步长：先预测并检查车身和所有已挂农具，再一起提交姿态；碰撞拒绝时保持最后安全位置。轮胎按实际位移滚动。
- 脱离后继续使用同一个模型实例和动态碰撞体，避免旧停车碰撞体、重复模型或重复所有权。下车检查也包含已挂农具。

## 存档

现有外层 SaveData 仍为 v2，`vehicles` 子结构升级到 version 2：

```ts
{
  version: 2,
  vehicles: [{ id, worldId: 'FARM', x, z, yaw }],
  implements: [{ id, worldId: 'FARM', x, z, yaw }],
  attachments: [{ vehicleId, implementId, port }]
}
```

仅保存可序列化数据；地面高度由原有地图重新计算。挂接与分离同步提交整组状态，再调用现有即时保存；行驶写入内存，沿用原有上下车、失焦、页面退出保存入口。速度、驾驶输入和乘坐状态不保存。

缺农业/车辆新增字段的旧存档按原流程加载。旧 vehicles v1 保留车辆姿态，农具使用默认位置。非法 ID、非有限坐标、不兼容端口、重复关系或悬空引用被过滤；地图验证失败时解除不安全连接并寻找原停放区安全位置。Inventory、Home Storage、Fishing、Cooking、Farm/Crop 和 GameClock 数据保持原接口。

本阶段没有物品转移：挂接和分离不读取或修改 Inventory / 仓库 / 土地状态。测试断言这些状态在挂接、行驶和分离前后不变；存档往返也保留现有背包和箱子物品数量。
