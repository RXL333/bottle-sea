# 玩家成长与解锁

按 **P**、工具栏的 **成长**，或画面左侧的当前目标卡片打开成长手记。P / Esc / 关闭按钮返回游戏。手记显示当前目标、操作地点与方法、已完成记录、实际解锁及明确标注的后续内容预留。

## 首版成长路线

15 个里程碑覆盖钓鱼、进入小屋、制作料理、睡觉、抵达农场、耕地、播种、收获、出售、购买、驾驶、喂养和领取畜产品，以及两个组合生活循环。玩家可按任意顺序完成；当前目标选取路线中第一个未完成项目。每项记录完成时的全局游戏时间；重复操作不重复记录或奖励。

新游戏首次完成料理后开放现有海鲜汤、烟熏鱼食谱；首次出售后开放现有仓库与车载粮仓升级商品。解锁不会自动发放物品、金币或升级，原有食材、体力、价格、升级顺序、容量和交付条件继续有效。基础烤鱼、旅行、农业、原有农机和畜牧保持开放。

缺少 progression 字段的 v1 / v2 旧存档保留上述原有食谱和升级访问权限；已有背包、金币、车辆、农田和容量不被回收。不根据背包中的鱼、料理或畜产品猜测历史操作，旧玩家以后真正完成对应动作时仍可记下新足迹。

## 模块边界

- `src/gameplay/progression/ProgressionRegistry.ts`：静态里程碑、路线顺序、提示、内容 ID 与解锁依赖。所有依赖必须先注册，不允许循环或未注册引用。动作里程碑与组合里程碑分开。
- `ProgressionState.ts`：`{ version: 1, completed: { milestoneId: gameTime }, grants: contentId[] }`，仅可序列化数据。校验时间和 ID；组合状态由依赖重建。旧档 grants 只覆盖此前实际存在的内容，不让后续系统自动全部解锁。
- `ProgressionSystem.ts`：全局游戏服务，提供 `record(activity)`、`completed(id)`、`completedAt(id)`、`currentObjective`、`isUnlocked(id)`、`canAccess(id)`、`lockReason(id)` 和 `snapshot()`。
- `GameplayFoundation`：创建唯一成长服务，独立注入 `ActivitySink`；已有 Fishing 的 `onEvent`、Cooking 的 `onResult` 仍由表现层使用，互不覆盖。
- `SaveSystem`：沿用 v2 顶层存档，增加 progression 字段，与所有已有玩法快照共同保存；加载不重播完成通知。
- `ProgressionPanel` / `ProgressionView`：只展示服务结果；完成提示使用独立队列，避免被钓鱼、做饭或交易提示覆盖。面板沿用现有暂停输入、恢复探索和鼠标锁定机制。

## 成功事件边界

| 活动 | 记录条件 |
| --- | --- |
| fish.catch | 抵抗成功并收竿完成，进入背包或现有暂存；抛竿、咬钩、失败不计 |
| cook.complete | 原有材料到成品交易已成功提交；取消或检查失败不计 |
| home.enter / farm.visit | 实际小屋切换或交通船抵达成功；加载失败与开发视角定位不计 |
| home.sleep | 时间推进、体力恢复已执行 |
| farm.till / seed / harvest | 至少一个土地单元成功提交；手工和农机共用；空操作、满容量和回滚不计 |
| vehicle.drive | 驾驶控制实际累计移动至少 0.5 米；仅上车或被障碍挡住不计 |
| livestock.feed / collect | 饲料扣除或产物转移成功；背包满时产物仍待领取 |
| trade.sell / buy | 原有经济交易成功；重放请求、扣款失败或交付回滚不计 |

通知与成长状态不持有任何物品数量或金币副本。成功事件记录会请求保存完整现有快照。

## 后续接入

后续系统先在 Registry 注册 milestone / unlock，再在业务成功提交后调用统一活动接口；真实入口使用 `canAccess(contentId)` 或 `lockReason(contentId)` 检查。`isUnlocked` 表示里程碑条件达成，`canAccess` 还要求内容确实已实现。

当前 NPC / 委托、图鉴、季节、深海 / 遗迹仅有预留条件，`implemented: false`。不会创建 NPC、任务、季节规则或修改旅行目的地权限。不包含等级、经验、技能树、每日任务。

## 验证

自动测试覆盖乱序完成、幂等、组合条件、失败与空操作、背包满、存档往返、旧存档授权、错误数据清理、未知内容拒绝、驾驶移动阈值。完整现有测试套件一并执行。

浏览器使用独立的 `127.0.0.1:5204` 存档验证，不修改用户正常开发地址的存档。使用现有 DEV 定位 / 物品 fixture；物品 fixture 本身不会完成成长。通过实际 E 交互、炉灶制作与商船交易验证事件，通过页面刷新和真实交通船往返验证恢复。截图在 `artifacts/progression/`。完整人工长时间游玩体验仍留给用户验收。

最终验证：typecheck 通过；66 个测试文件、292 项测试全部通过；build 通过。浏览器已实际检查首次料理解锁、出售与付费扩容、刷新恢复、进入小屋与睡觉、交通船往返、手工耕地、驾驶移动阈值、喂养与收蛋。浏览器控制台未发现警告或错误。钓鱼、播种与收获的浏览器完整流程本阶段未逐项重跑，对应自动测试已通过；长期完整人工游玩待用户验收。
