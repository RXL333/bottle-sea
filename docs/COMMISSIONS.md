# 岛民委托

在四位 NPC 身边按 E → 查看 / 接取 / 提交委托。J 打开委托手记；离开 NPC 后只能查看，不会远程交付。商船老板仍使用原有每日 08:00–20:00 靠岸规则。

首版 12 份固定、一次性、无期限委托：灯塔老人（旅行、旧锚、近岸遗迹）、渔夫（沙丁鱼、三次真实钓获、金枪鱼）、商船老板（亲手制作并交付烤鱼、小麦大宗交付、牛奶与羊毛）、农场管理员（小麦、六份真实作物收获、鸡蛋/牛奶/羊毛）。基础委托随时可接；小麦大宗订单通过既有 `home_cycle` 开放。

## 模块与真实数据

- `gameplay/commissions/CommissionRegistry.ts`：集中定义发布者、目标、奖励；引用 ItemRegistry、NPC Registry 和 Progression，不复制物品元数据。新增定义会检查 ID、数量、奖励、重复交付条目与解锁引用。
- `CommissionSystem`：可接取、进行中、可提交、已完成。交付读取当前 Inventory，储物箱、谷仓、粮仓需先取出。探索读取现有 PlayerState discoveries；旅行读取真实 Progression 里程碑。已有探索/抵达记录有效。
- 生产目标从接取后计数，只接收原玩法成功提交事件的 `produced` 明细。Fishing、Cooking、FarmSystem、LivestockSystem 继续拥有各自规则。手工和联合收割机都经过 FarmSystem；转运、交易、奖励与失败操作不计生产。钓鱼背包已满暂存时计一次，稍后领取不再计数。
- `CommissionPanel` 只显示服务返回的结果，复用 UIChrome、ItemIcon 与海岛 UI 主题，提供进度、物品、奖励、失败原因和完成记录。

## 交付、奖励与存档

先检查所有交付物品、真实生产/发现条件、扣除后全部奖励的接收容量和金币上限。使用 Inventory `canExchange/exchange`，金币进入既有 EconomySystem；配方和扩容访问权限使用 Progression `grant`，不伪造里程碑。重复、跨发布者和重入请求被拒绝；委托奖励不计入出售/购买成就。

GameplayFoundation 的嵌套批量保存收集提交过程中的变更，提交完成或回滚后才发布最终快照。意外奖励失败恢复库存、余额、解锁和委托原状态。完成标记永久防止重复领取；失败容量检查保留全部资源。满背包也可以提交，只要扣除后腾出的空间足够装下全部奖励。

SaveSystem 继续使用现有 v2 存档与键，新增 `commissions: {version:1,records}`。记录只保存接取时间、完成时间和每个生产目标的真实累计证据；不会保存模型、UI、库存副本、金币副本或可提交缓存。加载时重新计算交付与探索状态；旧存档无字段时为空委托记录，不回收已有物品和车辆。生产证据按目标上限校验，未知定义与损坏条目安全忽略。

新增委托只需注册定义，未来系统也可引用 Progression 的统一解锁能力。本阶段没有每日任务、倒计时、复杂任务链、好感度和随机无限委托。
