# 航海手记 / Collection

按 **N** 或 HUD「手记」打开，N / Esc / 关闭按钮收起。四位核心 NPC 的「翻看航海手记」也进入同一个面板。

## 配置与状态边界

`CollectionRegistry` 是展示适配层，引用 ItemRegistry、CropRegistry、CookingCatalog、LivestockDefinition、DestinationRegistry 和现有 LANDMARKS / JOURNAL_TEXT。首版 26 页：鱼类 6、作物 3、料理 4、动物与畜产品 6、岛屿与地点 4、特殊航海发现 3。数字来自真实配置，不按示例虚增数量。

`CollectionSystem` 只保存 `{ id, firstGameTime, sources }`。库存数量、作物状态、动物待领取产物、金币和玩家里程碑仍由原系统管理。查看图鉴没有任何解锁或奖励副作用。

未发现视图只提供类别、??? 和统一占位说明；不提供物品图标、真实名称、规则或描述。已发现视图直接读取原定义，并显示首次游戏日期、时间和来源。获得料理与亲手制作保留不同来源。

## 自动登记

- 背包、小屋箱子、谷仓出现真实持有物品时登记对应物品页；种子不会提前解锁尚未收获的作物。
- Fishing 成功钓获登记鱼类，作业中背包装满后保留的待领取鱼同样是已成功钓获；之后领取不重复增加完成度。
- Cooking 成功生成料理时增加「亲手制作」证据。失败、取消和仅查看食谱不能登记。
- 手工或农机成功收获登记作物，产物直接进入车载粮仓也有效。
- 实际近距离接近圈舍动物时登记动物；成功领取畜产品才登记产物。背包不足时待领取内容仍保留原系统状态。
- 成功加载 / 实际到达家园岛、农场岛或小屋登记地点；预加载和 TRAVEL 航行中不登记未抵达的岛屿。
- 原有 E 地标交互更新现有 Discovery，并在同一本手记保存日期与见闻；HUD 原地标列表升级为六类收集摘要。

库存观察在 GameplayFoundation 的保存事务边界读取最终状态，委托奖励失败回滚不会留下未获得物品的图鉴页。不改变原来的交付、容量与奖励规则。

## 存档与旧档

继续使用 v2 SaveSystem，新增 `collections` 子结构版本 1；仅序列化记录数据。加载时对条目、来源、日期与重复记录做校验。地标记录与现有 PlayerState / WorldState 的 Discovery 合并恢复，避免手记和地标交互各走一套。

缺失字段的旧档从背包、箱子、谷仓、车载粮仓 / 拖车、待领取鱼、实际饲养状态、已有地标和精确到达里程碑补录。精确的旧到达时间可以沿用；其他历史日期标为「旧航程记录 · 历史日期未保留」。泛化的首次钓鱼或制作里程碑不能推断具体鱼种或料理；已经消耗且没有历史证据的物品不虚构补录。

## 后续扩展

`record(reference, source)`、`has(id)`、`view(id)`、`list(category)`、`stats(category)` 和 `onDiscover` 提供统一入口。新鱼 / 作物 / 料理由原配置派生；新地点或特殊发现可注册展示引用，仍使用真实发现事件登记。NPC facts 已提供 `collectionCount / collectionTotal`；Progression 已接通手记内容入口。将来委托可读取同一查询接口，此版不加图鉴奖励、排行榜或每日任务。

`CollectionPreview` 仅在 DEV、显式 `view=collections&fixture=1` 下提供真实 API 检查点；生产构建不启用这些控制。
