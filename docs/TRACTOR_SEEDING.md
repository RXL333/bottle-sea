# 拖拉机挂载播种机播种

沿用现有 GLB、HitchSystem、车辆子步、连续扫幅、InteractionSystem、Inventory、FarmSystem、CropRegistry、GameClock 和 SaveSystem。没有新增种子仓或独立作物数据。

## 操作

1. E 上车，停稳并对准播种机连接点后按 H 挂接到后挂点。
2. 驾驶 HUD 选择小麦、玉米或土豆；鼠标锁定时用 **K** 按 Registry 顺序换种，无需释放鼠标。HUD 直接显示背包库存，按钮显示当前选择。
3. **J** 落下开启播种，W / S 前进或倒车、A / D 转弯。再次 J 抬起停止。只有已挂接、落下、正在驾驶且实际移动的播种机作业。
4. 每成功播种一格扣除对应种子 1 份。种子耗尽自动抬起停止，并持续显示“种子不足”；补充背包或换有库存的种子后，重新按 J 开启。
5. H 停稳分离，E 安全下车。步行种植继续使用已有快捷栏与手工交互，播种机选种不会改写快捷栏。

挂接与分离默认停止作业。切换至无库存的种子也停止；切换至有库存的种子保留当前抬落模式。若同时前挂犁、后挂播种机，J 操作播种机，前犁保持已有模式；独立作业仍按各自扫幅与数据规则处理。

## 数据与作业

- `ImplementRegistry` 为已有六组行单元定义实际播种范围。原资产六行中心间隔 0.43 米，覆盖 X [-1.29, 1.29]、glTF Z [-1.33, -0.67]；农场缩放 0.5 后宽 **1.29 米**。宽度来自播种行，排除料斗及运输轮。
- `SeedingSystem` 是模型无关的薄接口，通过原 `ImplementSweep` 连续多边形扫描与 `FarmSystem.cellsInArea` 的单元中心覆盖规则确定单元。候选去重，仅保留 TILLED 且 crop 为 null 的土地。
- 路面、建筑、草地、预留区没有农田单元，不会播种。UNTILLED、HARVESTED 均不播种；SEEDED、GROWING、MATURE 全部保护，切换作物与重复经过也不能覆盖。
- 可用数量来自 `Inventory.count(registry.get(cropId).seedItemId)`。库存不足以覆盖当前扫幅时，只提交可用份数对应的单元，其余保留已耕；调用与手工一致的 `FarmSystem.seed`，由原库存事务同时提交扣种及农业状态。
- 成功种植后使用 Registry 的阶段与模型、全局 GameClock 播种时间。原 FarmCropPresentation 根据共享 revision 当帧显示，离岛及睡觉成长机制不变。
- 不修改成熟时间、收获数量、背包容量、Home / Fishing / Cooking，也不产生收获物或重复收益。

## 保存

外层 SaveData 与车辆子结构仍为 version 2。播种机增加已支持的 `workState` 和 `seedCropId`，仅存字符串及原有位置 / 关系。旧播种机默认 RAISED，种子默认 Registry 第一种；非法 cropId 归一化为安全默认，其他农具不保存选种字段，拖车不接受作业模式。

每次播种前记录当前整组车辆 / 农具姿态和选择；若本次用完种子，先记录 RAISED，再进入农业事务。Inventory 的保存回调和 FarmSystem 的即时保存都能看到一致的“已扣种 + 已播种 + 已停机”状态。切换作物或作业开关同样即时保存，恢复位置不执行播种。

作业计数仅是本次反馈，重新进入或切换种子 / 模式会重置。库存、作物 ID、播种时间、当前阶段、车辆 / 农具位置、选种、模式、关系均使用已有存档链路恢复。
